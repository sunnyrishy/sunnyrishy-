## 🧠 About Me

<div align="center">
<img src="https://img.shields.io/badge/-000000?style=for-the-badge" width="0" height="0"/>
</div>

I'm a **Software Engineer** with a systems-first mindset — I build things that need to be *fast, correct, and production-ready*, from lock-free C++ engines processing millions of ticks per second to full-stack applications shipped end-to-end.

My core strength is **low-latency, multithreaded systems programming in modern C++** (STL, lock-free queues, memory-mapped I/O, CPU affinity), sharpened by years of competitive programming (LeetCode, Codeforces). Alongside that, I actively build in **AI/ML and agentic systems** — from LLM-driven autonomous software pipelines to hybrid quantum-classical neural networks — because I believe the most interesting engineering problems today sit at the intersection of systems performance and intelligent automation.

I hold an **M.S. in Computer and Information Sciences from Adelphi University** (GPA 3.84), where I worked as a **Graduate Research Assistant** on approximation algorithms for large-scale advertising systems, and a **B.Tech from NIT Andhra Pradesh**.

- 🤖 AI/ML engineering — LLM integration, agentic pipelines, hybrid quantum-classical ML
- 🧩 Product engineering mindset — I care about correctness, performance, and shipping
- 🏆 Competitive programmer — Codeforces Pupil, active LeetCode grinder

## 🚀 Featured Projects

<details open>
<summary><b>⚡ High-Frequency Trading Simulation Engine</b></summary>
<br/>

A low-latency order-matching and backtesting engine built in modern C++, simulating the core of an HFT system — order lifecycle management, strategy execution, and sub-microsecond matching.

| | |
|---|---|
| **Stack** | C++17, STL (map/list-based order books), CMake, Python (analysis tooling) |
| **Scale** | Full order lifecycle (new / partial fill / fill / cancel), multiple strategies (SMA, Mean Reversion, Market Making) |
| **Performance** | Order insertion ~100–500ns · Matching ~200–800ns · Cancellation ~50–200ns — sub-microsecond throughout |
| **Security** | Integer tick-based pricing (no floating-point drift), RAII/smart-pointer memory safety |
| **Impact** | Demonstrates production-grade low-latency systems design applicable to quant trading and HFT infrastructure roles |
| **Repository** | [github.com/sunnyrishy/high-frequency-trading-engine](https://github.com/sunnyrishy/high-frequency-trading-engine) |

</details>

<br/>

A production-style REST API built entirely in C++17 using the Drogon framework, backed by PostgreSQL — showing that C++ can power modern, secure, containerized backend services, not just embedded/systems code.

| | |
